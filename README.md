## 1. Создание проекта TeamCity

Создан проект TeamCity на основе собственного fork репозитория `example-teamcity`.

## 2. Автоматическое обнаружение конфигурации

Выполнено Autodetect configuration. TeamCity обнаружил конфигурацию Maven и создал Build Configuration.

## 3. Первая сборка master

Сохранены необходимые шаги сборки и запущена первая сборка ветки `master`.

## 4. Условия выполнения сборки

Настроено условие: для ветки `master` выполняется `mvn clean deploy`, для остальных веток — `mvn clean test`.

## 5. Настройка Maven для Nexus

В TeamCity загружен `settings.xml` с настройками Maven и учётными данными для подключения к Nexus.

## 6. Настройка pom.xml

В `pom.xml` изменены ссылки на репозитории и Nexus для публикации Maven-артефактов.

## 7. Проверка публикации в Nexus

Запущена сборка `master`. Сборка завершилась успешно, артефакт опубликован в Nexus.

## 8. Миграция конфигурации Build Configuration

Настроено хранение конфигурации TeamCity в GitHub через Versioned Settings (Kotlin DSL). Конфигурация сборки сохранена в репозитории в каталоге `.teamcity`.

## 9. Создание feature-ветки

Создана отдельная ветка `feature/add_reply` для внесения изменений в код.

## 10. Добавление метода Welcomer

В класс `Welcomer` добавлен метод `sayHunter()`, возвращающий реплику со словом `hunter`.

Файл `src/main/java/plaindoll/Welcomer.java`:

```java
public String sayHunter() {
    return "Good luck, hunter!";
}
```

## 11. Добавление теста

В `WelcomerTest.java` добавлен тест, проверяющий наличие слова `hunter` в ответе нового метода.

```java
@Test
public void welcomerSaysHunter() {
    assertThat(welcomer.sayHunter(), containsString("hunter"));
}
```

## 12. Push изменений

Изменения метода и теста отправлены в GitHub в ветку `feature/add_reply`.

## 13. Проверка автоматической сборки

После отправки изменений TeamCity автоматически запустил сборку. Сборка завершилась успешно, все 5 тестов прошли.

## 14. Merge в master

Изменения из `feature/add_reply` объединены с веткой `master` через Pull Request и Merge в GitHub.

## 15. Проверка сборки master

После Merge запущена сборка `master`. Сборка прошла успешно, ошибок публикации артефактов не возникло.

## 16. Настройка публикации JAR

В TeamCity настроено правило публикации артефактов:

```text
target/*.jar
```

Артефакты публикуются даже при неудачной сборке.

## 17. Повторная сборка master

Повторно запущена сборка `master`. Сборка завершилась успешно, JAR создан и опубликован в Nexus, артефакты сборки доступны в TeamCity.

## 18. Проверка конфигурации в GitHub

Проверено, что в GitHub присутствует каталог `.teamcity` с файлами:

- `settings.kts`
- `pom.xml`
- `pluginData/_Self/mavenSettings`

В `settings.kts` сохранены шаги Maven, условие для `master` и правило публикации JAR.

В TeamCity Versioned Settings включена синхронизация с GitHub.

## Итог

Настроена автоматическая сборка проекта в TeamCity с интеграцией Nexus.

Добавлены метод `sayHunter()` и тест на наличие слова `hunter`. Изменения объединены в `master`.

JAR публикуется в Nexus и как артефакт TeamCity. Конфигурация Build Configuration хранится в GitHub через Kotlin DSL.
